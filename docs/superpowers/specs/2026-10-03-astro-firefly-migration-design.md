# Astro + Firefly 科研知识主页迁移设计

日期：2026-10-03。状态：讨论中的各节设计及书面规格已获用户确认；[详细实施计划](../plans/2026-10-03-astro-firefly-migration.md)已形成，等待审阅与执行方式选择，尚未开始 Astro 应用迁移。

## 1. 目标与已确认决策

将现有 Next.js 个人博客迁移为以 Astro + Firefly 为基础的长期科研知识主页。网站服务于课程学习、论文阅读、科研日志、研究想法、实验和项目积累，内容增长到 500+ 篇后仍能通过课程、类型、主题和全文搜索找到记录。

用户已确认：

- 采用 A 路线：直接使用 Firefly 应用与组件，适配科研内容，在独立分支完成迁移后统一切换。
- 使用类型、主题、课程关系和发布状态组织内容；一篇正文只有一个稳定地址。
- 启用视频横幅、音乐、打字机、波浪/渐变、毛玻璃、轻量樱花及页面过渡。
- 首页呈现 Firefly 的完整风格；文章正文具有稳定清晰的背景，媒体和装饰可控制。
- 先验证代表文章，再全量迁移；保存恢复基线，完成内容、链接、规模与媒体验收后安排正式发布。

文档继续在 Git 中维护，首版静态发布。技术选择与交互都围绕上述任务，不增加 CMS、账户系统、AI 问答、知识图谱或文献数据库。

本规格是后续详细实施计划的依据。[ASTRO_MIGRATION.md](../../../ASTRO_MIGRATION.md)保留内容盘点、53 条源记录归属和迁移背景；[AUDIT.md](../../../AUDIT.md)与[REDESIGN.md](../../../REDESIGN.md)保留前期审计依据。关于框架和视觉效果，以本规格为准，明确取代旧文档继续使用 Next.js、禁用视频及动画的建议。

迁移期间仍以原内容库为唯一编辑来源。若继续写作，重新生成副本并复核迁移清单；正式切换后唯一正文来源变为 `src/content/posts`，不建立长期双向同步。

## 4. 内容模型

### 4.1 共同字段与关系

| 字段 | 契约 |
| --- | --- |
| `id` | 显式稳定业务 ID，从当前有效加载结果导出；后续移动文件不改变 ID |
| `slug` | 显式唯一地址段，正文路由使用此字段；改标题、类型和目录不重新生成 |
| `title` / `description` | 保留当前有效标题与摘要；新文章提供可区分的完整标题和摘要 |
| `contentKind` | `note` 或 `collection`，区分正文与集合介绍 |
| `type` | `course`、`paper`、`log`、`idea`、`experiment`、`note` 六种用途，每篇一个 |
| `topics` | 多选受控主题 ID；首版沿用现有扁平词表 |
| `course` | 课程讲义的稳定课程 ID 与讲次顺序，顺序不由日期推导 |
| `visibility` | 显式 `published`、`unlisted`、`draft` |
| `date` / `updatedAt` | 可选真实日期，保留已有日精度；更新时间来自实质内容更新 |

旧 `tags/category` 作为迁移来源记录保留；公开组织共用上述字段，不为每个页面重复维护分类规则。课程与主题的稳定 ID、名称和说明集中定义，未知 ID、重复 slug 或不合法讲次应报错到源文件。

模板需要的 `published/updated`、系列与导航展示由统一适配方法读取这些事实；不在源文档写回两份日期或两份课程顺序。模板的必填日期要求需适配为本站的可选日期语义，并覆盖排序、归档、RSS 和文章展示。

### 4.2 类型专有资料

- 课程页保存课程介绍、来源和有序讲义。课程正文按同课程顺序提供上一讲/下一讲。
- 论文笔记可以记录真实论文题目、作者、发表年份、会议及 Paper/arXiv/DOI/Code 链接。发表年份和笔记写作日期分开；只有实际数据对应的筛选与来源按钮才显示。
- Research 聚合日志、想法和实验。已有日志不转为主题的碎片动态，也不强制重写历史正文结构。
- Project 是独立项目资料，可关联笔记；有真实资料时显示目标、状态和代码/成果入口，不作为第七种笔记类型。

### 4.3 公开范围

正文进入列表、计数、推荐、搜索、订阅及 sitemap 共用一个公开判断：`published`、非空、`contentKind=note`。公开课程、主题、研究和真实项目集合另行进入 sitemap，其成员列表和计数仍使用同一个正文判断；集合介绍不进入文章结果。

`unlisted` 非空笔记可通过地址访问，设置 noindex，并从公开发现入口排除。`draft` 不输出正文页面。空讲义的旧地址进入说明缺少正文的课程上下文。日期未知的公开笔记仍可浏览与搜索，时间列表排在已知日期后；首版 RSS 只纳入具有可信日期的公开笔记，sitemap 不伪造 lastmod。

首页顺序为视频身份横幅、课程/论文/研究/项目入口、少量真实精选、最近公开记录、About/联系入口。个人名称、头像、社交链接和研究介绍取自真实资料；不保留模板作者身份。没有精选或项目内容时省略对应首页内容块，保留集合的真实空状态。

## 6. 视频、音乐与装饰体验

### 6.1 首版启用项

沿用 Firefly 的视频横幅、导航/浮层毛玻璃、圆角面板、主题色、打字机、横幅波浪与主题渐变、轻量樱花和 Swup 页面过渡。波浪/渐变按模板现有逻辑切换，不额外叠加一套相同效果。樱花初始约 8–12 个粒子，并在手机降低密度。

首页横幅初始参考桌面 300–420px、手机 180–240px，原型以身份和内容入口是否容易到达为准。文章页缩短横幅，视频不进入正文背景；装饰层不拦截点击、不遮住代码、公式和目录。

未指定素材时，先用模板示例完成本地原型；生产所用视频、静态封面和音乐列表记录来源及路径，并在正式发布前选定。相册、追番、游戏资料、打赏、留言板、看板娘、评论和追踪不属于首版迁移范围。

### 6.2 播放与生命周期

- 视频静音、行内、循环播放，具有封面和可见播放/暂停控制。正常模式尝试自动播放；被阻止或加载失败时显示封面并允许点击播放。
- 导航和侧栏共用一个音频实例，音乐由用户点击后播放。初始音量约 0.25，提供音量、暂停和静音控制，优先采用 local 播放列表；明确选用在线歌单后才接入 Meting。
- 站内切页保留用户已开始的音乐及播放位置，不重复启动。刷新后不根据保存状态自行发声；音量和曲目选择可恢复。
- Swup 切页、返回与 hash 导航不能重复创建音频、视频控制器、粒子或监听器；搜索、目录、焦点与读屏行为需同时验证。
- 非前台页面暂停背景视频与装饰动画；音乐继续遵循用户的播放操作。

### 6.3 控制与降级

提供可见的统一“暂停动态效果”控制，作用于视频、打字机、波浪、樱花与页面过渡，并保存选择。该控制不替用户改变音乐播放状态。

没有用户覆盖选择时，`prefers-reduced-motion` 使用静态封面、完整文字与普通导航，音乐仍可手动播放。节省流量模式不预取视频/音频，并使用封面。移动端正常模式仍保留效果和媒体入口；紧凑播放器不遮住正文与底部操作。

封面、文字、内容入口和正文先显示，音乐不在首屏下载完整音频。视频、音频或歌单失败只影响相应媒体；页面导航、正文和搜索不等待媒体成功。按钮具备可见焦点和读屏名称。没有 JavaScript 时正文、课程、分页和原生锚点仍可读可用，搜索页说明全文检索需要 JavaScript 并提供集合入口。

## 7. 构建架构与职责

采用一套 Astro Content Collection 承载现有正文与集合介绍，普通 Markdown 保持 `.md`，仅真正嵌入组件的新文章使用 MDX。

| 部分 | 输入与输出 | 责任边界 |
| --- | --- | --- |
| 迁移转换 | 原工作区实际文档、目录定义与资产 → 副本及 manifest | 导出稳定事实、保全正文与原图，不长期同步两套内容 |
| 内容 schema 与目录 | frontmatter、课程/主题定义 → 校验后的条目 | ID/slug/引用/日期/顺序与公开范围的共同来源 |
| 渲染管线 | 条目与相对资源 → HTML、真实 headings、静态资产 | Markdown 兼容、公式、图表、图片、锚点，不返回 React MDX 节点 |
| Firefly 页面 | 校验后的元数据与渲染结果 → 静态正文/集合/分页 | 展示与局部交互；课程导航只携带当前课程上下文 |
| Pagefind | 明确标记的公开正文 HTML → 搜索索引 | 排除导航、媒体、TOC、重复集合正文与 unlisted |
| 发布配置 | dist、正式 origin、平台能力、旧 URL 清单 → 发布包与重定向规则 | SEO、资源和 URL 同版交付，预览与正式配置有明确区别 |

先记录并锁定 Firefly 上游提交及许可证，再以其应用为根应用，保留必要 Svelte 与 Swup 交互。Node、pnpm 和唯一 `pnpm-lock.yaml` 使用所锁定模板支持的版本，CI 与本地一致。上游构建任务逐项核实，保留本站实际使用的步骤，检查使用中的媒体与效果资源是否被裁剪。CI 检查不能使用会修改源码的 lint 参数。

迁移不把 Next.js 页面逐个翻译为 Astro，不保留 React 正文编译、手写文件扫描或运行时图片转换作为新站基础。

## 8. 正文、图片与搜索兼容

### 8.1 渲染

优先复用 Firefly 的数学、代码高亮、Callout 和图表能力。验证 GFM、长公式、MathML、代码元信息、复制按钮、Callout 的折叠/嵌套、中文与重复标题、Typora 高亮/上标/下标、宽表格及原始 HTML 图片。

现有 React MDX JSX 插件只迁移必要的语法识别，输出适合 Astro Markdown 的节点。TOC 来自实际渲染 headings；`[toc]` 不额外产生重复目录。正文中的标题调整通过渲染处理，并保留必要旧锚点，不通过重写整篇 Markdown 整理格式。

优先验证主题现有构建时静态 SVG 对全部 10 个含 Mermaid 文件的兼容。构建成功不代表图表正确；逐项检查文字、节点与关系。若实际不兼容才采用按页面加载的浏览器 Mermaid，并记录原因，不默认维护两套引擎。

### 8.2 图片

将 `content/posts` 整体迁至 `src/content/posts`，保留子目录、相邻 assets 和历史目录拼写；公开地址不依赖这些拼写。原图按字节保留，阅读资源在构建时生成。

Markdown 图片与原始 HTML img 分别验证处理路径；HTML 图片不能假定自动进入 Astro 资源优化。发布输出具有真实宽高和响应式变体，科学截图可查看原图；现有 zoom/缩放含义保留。所有图片引用按源文档位置解析，缺失资源明确报错。未引用原图保留在源库，不无差别发布。

### 8.3 搜索与规模

采用 Pagefind，以唯一公开正文生成索引，支持类型、主题、课程筛选。索引覆盖标题、摘要、章节与正文；结果展示可区分的标题、类型/课程和命中片段。

检索 URL 的 query 与筛选可复制、刷新和返回恢复。空 query 展示使用说明与入口；无结果可解除筛选。统一检索中英日内容，采用适合 CJK 的构建与语言配置，并以真实查询核验。公式符号精确搜索不作为首版承诺。

每页约 25 项，只生成实际类型、课程、主题和分页；不生成所有筛选组合，不把整站全文注入首页、侧栏或每篇文章。

## 9. URL、SEO 与发布输入

正文 canonical 统一为 `/notes/[slug]`，兼容原 `/blog/<路径>` 和上一轮形成的 `/notes/...` 地址。模板 `/posts` 不产生第二套可索引正文。最终尾斜杠形式统一，旧地址直接进入最终规范地址。

53 个源记录的初始路径归属使用 ASTRO_MIGRATION 附录。旧 `/blog` 的 folder/category/tag 查询、`/notes` 的分页/筛选、`/authors/...` 与 `/research/areas/...` 按真实含义兼容，不全部跳首页。中文、空格、加号及百分号编码单独验证。fragment 不参与服务器重定向，变化的标题 ID 用正文锚点兼容。

旧 `/api/images/<路径>` 根据原图到静态资源的显式映射兼容；旧 `?w=` 请求进入实际生成的资源，不继续提供动态变换。映射只暴露对应公开资产，不用任意文件通配替换。

Astro 静态 redirect 页面不替代真实 HTTP 301/308。正式平台确定后，使用该平台的规则落实路径和查询语义；资源、搜索索引、SEO 与规则作为同一发布版本。

正式发布有三个外部输入：生产 origin、当前托管平台及项目、最终媒体清单。在这些输入提供前交付本地/预览站和验证报告，不执行正式域名切换。输入提供后沿用当前域名和平台，配置正式 canonical、RSS、sitemap 与 robots；不把环境回退值或历史 CI 当作线上平台证据。预览使用 noindex，正式构建禁止临时域名和 localhost 元数据。

保留 Firefly/Fuwari 来源及 MIT 版权声明，记录上游提交；升级通过差异合并，不覆盖正文库。

## 10. 迁移与故障处理

顺序为：恢复基线与 manifest → 真实文章原型 → 全量文档/图片 → 集合与搜索 → 完整验收与发布准备。详细任务、命令、文件范围和执行方法在书面规格审阅后形成独立实施计划。

manifest 记录源/目标路径、稳定 ID/slug、类型/主题/课程关系、公开状态、正文及图片 SHA-256、旧 URL、canonical、静态资产映射和标题锚点差异。正文 hash 排除 frontmatter，图片按原始字节。

转换具有 dry-run；再次执行不重复增加元数据或改变已经确认的 slug。必要正文修正逐项记录 diff，其余正文 hash 相等。原型包含编译原理/操作系统长文、公式论文、Callout、日志、日语与 Typora 示例。

- 重复 ID/slug、不合法元数据、缺失资源、错误课程关系及无法映射的源记录阻止进入发布准备，并给出源文件位置。
- 图表错误不得凭“构建通过”放行；修复兼容或使用已说明的回退管线后复验。
- 视频、音乐或装饰失败降级到稳定正文与静态界面，不阻断文章输出。
- 内容、旧链接或资源存在阻断时不正式发布；修复后重新生成同版产物。
