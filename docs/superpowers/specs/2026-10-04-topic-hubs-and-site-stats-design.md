# Goongmly 专题聚合、主题导航与站点统计设计

日期：2026-10-04。状态：对话设计及本书面规格均已获用户确认。下一步编制实施计划，此阶段不修改应用代码。

## 1. 目标与已确认决策

将个人科研知识主页的发现方式调整为“专题入口 → 主题集合 → 文章”，在内容增长到 500+ 篇后，仍能按课程或研究方向找到内容、连续阅读并确认当前位置。

用户已确认：

- 取消 Notes 顶层入口，保留 Courses、Papers、Research、Projects 四个入口。
- 四个入口采用参考站的专题聚合方式，展示主题名称、简介和文章数量。
- 左侧提供随当前专题变化的主题导航、篇数和当前状态；课程文章额外提供讲次导航。
- 右侧提供文章、分类、标签、总字数、运行时长、最后活动六项站点统计；文章页的阅读目录优先于统计。
- 手机端采用单栏，主题导航可展开，统计放在内容末尾。
- 运行时长从配置中的 `2025-01-01` 起算，采用 `Asia/Shanghai` 的自然日，建站当天为第 0 天。
- 文章列表分页，统计在构建时统一汇总；已有文章地址继续有效。

本规格更新 [Astro + Firefly 迁移设计](2026-10-03-astro-firefly-migration-design.md)中关于主导航、集合页与侧栏的部分。正文和原图保全、唯一文章地址、公开范围、课程顺序和搜索边界继续沿用已有契约。

实施工作区仍为 `.worktrees/astro-firefly`，分支为 `feat/astro-firefly`；当前基线提交为 `efe01f2`。本次设计对应本地 Astro 网站，不包含部署、合并或修改原 main 工作区。

## 2. 参考与实现方向

- [喵斯基部落专题页](https://blog.moewah.com/hubs/)：参考“主题名称、简短说明、内容数量”的聚合入口及两侧栏布局。
- [参考专题详情页](https://blog.moewah.com/hubs/astro-blog-setup-guide/)：参考介绍、文章列表、分页和专题导航之间的关系。
- 现有 Firefly 的 `WidgetLayout`、`SiteStats`、`SidebarTOC`、`Profile`、`Music` 及网格布局作为实现基础；课程导航继续使用本站已有 `CourseNav`。

推荐保持四个导航入口，各自在内部提供主题聚合。将四个入口合并到单一“专题”页面会增加一次选择步骤；用户已选择前一种结构。

参考站用于确认信息组织和交互，其源代码不是实施依赖。需要参考其他开源博客实现时，核对实际源文件和许可证，并优先复用当前项目的能力。保留已确认的蓝色主题、自定义背景媒体和装饰控制。

## 3. 内容层级与归属

| 层级 | 定义 | 示例 |
| --- | --- | --- |
| 专题入口 | 四个固定的内容用途入口 | Courses、Papers、Research、Projects |
| 主题集合 | 当前入口内的课程或研究方向 | 强化学习课程、机器人论文、三维视觉研究 |
| 文章／项目正文 | 一个稳定地址对应一份正文 | 强化学习 Lec2、DeepMimic 阅读笔记 |
| 标签 | 具体关键词，辅助检索 | 方法、工具、数据集等已有标签 |

### 3.1 四个入口

| 入口 | 成员范围 | 分组方式 | 组内默认顺序 |
| --- | --- | --- | --- |
| Courses | 公开且非空的 `type=course` 正文 | 现有稳定 `course.id`，课程名及介绍来自课程目录 | 已有讲次顺序，未设顺序者排后；不按日期重排课程 |
| Papers | 公开且非空的 `type=paper` 正文 | 受控 `topics` 研究方向 | 置顶优先，再按发布日期倒序；未知日期排后、稳定排序 |
| Research | 公开且非空的 `log`、`idea`、`experiment` 正文 | 受控 `topics` 研究方向 | 与 Papers 相同；日志、想法、实验为附加用途入口 |
| Projects | 非 draft 且有正文的公开项目 | 使用同一受控主题词表 | 沿用项目的手动排序、发布日期和标题排序 |

课程目录中已配置但没有公开讲义的课程允许显示真实的零篇状态；不展示未公开讲义的标题。Papers、Research、Projects 的主题入口只展示实际有公开成员的主题。暂无公开项目时保留空状态，不补充演示项目或虚构分类。

一篇论文或研究记录可以属于多个主题：它在多个集合中出现，但始终进入同一篇正文。各主题篇数可能重叠，不相加作为全站文章数。主题导航按目录中的稳定顺序排列，新增主题显式写入目录，排序不随文章数量变化。

Papers、Research、Projects 中没有主题的公开内容放在该入口的“未设置主题”集合，仍可访问和检索；它不算作一个已配置分类。公开的 `type=course` 正文必须引用合法 `course.id`，缺少时明确报错到源文件，避免讲义被静默遗漏。不根据旧目录拼写、标题关键词或文件路径猜测新的主题。

### 3.2 元数据与公开边界

- 文章继续使用 `id`、`slug`、`contentKind`、`type`、`topics`、`course`、`visibility`、`date`、`updatedAt` 和现有标签。
- 专题入口由已有用途字段派生，不在 frontmatter 再维护一份 `hub` 字段。受控主题的名称和说明继续由 `src/data/catalog.ts` 提供。
- 为项目增加可选 `topics`，默认空数组并校验受控 ID；增加可选真实更新日期 `updated`，继续沿用项目已有 `published` 日期格式。已有项目地址不重新生成。
- 列表、计数、主题导航和统计共用公开判断。专题介绍不计为文章；draft、unlisted、空正文不进入公开发现入口或统计。
- 删除 Notes 入口不删除 Markdown、现有 `note` 类型或演示地址。通用 `note` 不自动归入四个专题；满足公开条件时，仍可通过兼容总览、跨专题主题页、首页最近记录及搜索发现。当前公开内容没有通用 `note`。

当前可核对基线：44 篇公开正文，包括 31 篇课程、12 篇论文、1 篇研究日志；公开项目为 0。实际使用的受控主题为 9 个，标签为 21 个。这些数字由内容计算，不写死在组件中。

## 4. 页面与路由

| 地址 | 设计职责 |
| --- | --- |
| `/` | 身份横幅、四个专题入口、真实精选和最近记录 |
| `/courses/` | 课程聚合页，显示课程介绍和公开讲义数 |
| `/courses/[id]/` | 课程介绍、按讲次排列的文章列表 |
| `/papers/` | 论文主题聚合页，不一次铺开全部论文 |
| `/papers/topics/[id]/` | 当前论文主题的分页文章列表 |
| `/research/` | 研究主题聚合页，保留日志／想法／实验的用途入口 |
| `/research/topics/[id]/` | 当前研究主题的分页文章列表 |
| `/research/logs/`、`/research/ideas/`、`/research/experiments/` | 保留已有用途列表，增加分页及专题上下文 |
| `/projects/` | 项目主题聚合页或真实空状态 |
| `/projects/topics/[id]/` | 当前项目主题的分页项目列表 |
| `/notes/[slug]/` | 已有文章的唯一正文地址 |
| `/projects/[slug]/` | 已有项目正文地址 |
| `/topics/`、`/topics/[id]/` | 保留跨专题主题索引与文章关联入口 |
| `/notes/`、`/notes/page/[n]/` | 保留兼容总览与分页，不作为主导航入口 |
| `/search/` | 保留 Pagefind 全文检索及已有筛选；有公开项目正文时支持项目检索 |

Papers、Research、Projects 的“未设置主题”集合使用其 `topics/uncategorized/` 路径，`uncategorized` 作为保留地址段，不可作为受控主题 ID。只有实际存在未设主题的公开内容时才生成该集合。

列表每页 25 项，第一页为集合地址，后续使用其下的 `/page/[n]/`。保留现有 `/notes/page/[n]/` 格式。只生成有实际内容的分页，超出范围和未知主题保持 404；显式配置的零篇课程页继续有效。

课程列表也使用静态分页；当前课程的讲次导航仍提供完整讲次关系，保持原有上一讲／下一讲。Research 的用途页与研究主题页分别提供一种浏览方式，不生成全部用途与主题组合页；组合筛选继续交给搜索。

### 4.1 专题页信息层级

1. 标题与两行以内的用途说明。
2. 已有公开专题介绍，有内容时展示，长介绍使用原生可展开区域，避免将主题入口推到页面很下方。
3. 主题集合入口：名称、简短说明、公开文章数，整行可点击，具备清楚的悬停与键盘焦点。
4. 必要的搜索或用途入口。搜索链接可预设当前内容类型，复用现有搜索筛选，不新增检索服务。

主题详情页显示返回专题、主题名称、简介、篇数与分页列表。列表摘要保持紧凑，显示真实课程／用途／主题，不继续由 `NoteList` 向 `PostCard` 固定传入空分类而将所有内容标为“未分类”。

### 4.2 首页与现有入口

主导航在桌面和手机均为“首页、Courses、Papers、Research、Projects”。Goongmly 的站点名称不因取消 Notes 导航项而改名。

首页四个专题入口补充真实内容数；保留精选与最近记录。最近记录的“全部笔记”入口改为“搜索记录”，指向 `/search/`。搜索备用导航优先提供四个专题与跨专题主题索引，不突出被取消的 Notes 入口。

公开项目正文遵循同一搜索边界，使用项目类型和受控主题标记；仍由 Pagefind 索引，不在客户端拼接另一套搜索结果。当前项目为零时，不制造项目结果。

## 5. 左侧专题栏、文章上下文与切页

专题和主题页的左侧顺序为：

1. 当前专题的主题导航：专题名称、全部主题、篇数、当前选中状态。
2. 当前课程的讲次导航，仅在课程详情或课程文章需要时展示。
3. 个人资料与音乐，继续保留其功能和用户已开始的播放状态。

首页及不属于四个专题的页面显示四个专题入口。文章从元数据确定所属专题；课程文章选中对应课程，其他文章标记其实际所属主题。多主题文章允许标记多个相关主题，不依赖浏览器 referrer 或临时点击顺序推导归属。

主题页使用 `aria-current="page"` 标记当前主题，课程讲次导航标记当前文章。多主题文章上的相关主题使用明确的相关状态，不伪称多个链接都是当前页面。长主题列表可在侧栏内滚动，全部主题可达，完整标题可通过换行阅读。

Swup 切页时更新专题名称、主题列表、选中状态和课程讲次；直接打开、刷新、浏览器返回及键盘导航均得到相同上下文。专题导航属于页面动态区域；头像、音乐和全站统计属于稳定区域。利用已有替换容器更新必要内容，不整体替换音乐实例。

所有相关页面保留 Swup 所需的容器或占位节点；避免重复 DOM ID、重复监听器和过期的侧栏上下文。侧栏导航和统计不进入 Pagefind 正文索引。

## 6. 右侧站点统计

右侧在首页、专题页、主题页和文章页均显示全站统计，不因当前主题而改变总数。文章页顺序为“本文目录 → 站点统计”；目录优先可达并保持原有标题锚点行为。

| 指标 | 精确口径 |
| --- | --- |
| 文章 | 公开且非空的文章与公开项目正文，按内容身份去重；集合介绍、草稿、unlisted、空正文不计入 |
| 分类 | 上述公开内容实际使用的受控主题 ID 去重；跨入口相同 ID 只计一次；不是四个入口数、旧 `category` 数或课程目录数 |
| 标签 | 上述公开内容的标签去空值、去重复后的种类数，展示名沿用现有标签规则 |
| 总字数 | 使用统一正文文本统计，中文按字、英文按词，汇总每篇公开正文一次；专题介绍和侧栏文案不计入 |
| 运行时长 | 上海时区当前日期与 `2025-01-01` 的自然日差，建站当天为 0 天 |
| 最后活动 | 全部符合公开范围的内容中，真实发布日期或更新日期的最大值；不是 Git 提交、文件 mtime 或构建时间 |

文章的去重身份使用带集合命名空间的稳定 ID，项目使用带集合命名空间的既有规范地址；不同集合的同名条目不会互相覆盖。主题中的重复成员引用不会重复计数。

总字数复用并统一现有 Markdown AST／`reading-time` 统计，与文章阅读信息采用同一文本及计数规则；不使用 SiteStats 现有的“每个英文字母算一个字”算法，也不为每页重新扫描全站正文。代码、公式的计入方式沿用统一正文统计，不修改它们的渲染或原文。

无可信活动日期时显示“日期未记录”。未来活动日期显示实际日期并标注日期待核实，不使用绝对值将未来日期算成“几天前”。运行天数下限为 0；日期差按自然日计算，不用毫秒差向上取整。

例如在 `2026-10-04`，以 `2025-01-01` 为起点，运行时长为 641 天。字数使用千位分隔；数字变化不改变条目对齐。

构建输出真实统计数值、起始日期和可信的最后活动日期。浏览器只更新天数和相对时间；页面切换不重复注册定时器或监听器。无 JavaScript 时保留构建时的天数和实际日期，不显示虚假的 0 天占位值。

## 7. 响应式布局与视觉

- 宽屏三栏：左侧主题导航、中间内容、右侧统计／目录。侧栏约 240–260px，间距沿用现有布局；正文可用宽度低于约 640px 时优先收起右栏。
- 中屏采用主题导航与正文两栏，统计移到内容末尾；文章目录使用现有可展开目录入口。
- 手机为单栏：标题之后、正文列表之前提供原生可展开的主题导航；课程讲次提供独立可展开区域；统计放在主体内容末尾。
- 所有尺寸均有主题导航和统计入口，收起桌面栏不等于丢失其信息。使用唯一组件实例或唯一 DOM ID，避免桌面／手机副本造成重复控制器。
- 文章正文维持稳定背景、现有字体、公式横向滚动和图片居中。统计与导航的字号和宽度不挤压阅读区。
- 延续蓝色强调色、现有圆角与间距；主题集合使用清楚的标题、说明、数量和轻边界，不新增渐变、玻璃效果或装饰动画。
- 键盘可展开、可选主题、可访问全部项目，有可见焦点。长中文标题和中英文混排可换行；320px 宽度不产生页面级横向溢出。

## 8. 实现职责与规模要求

| 部分 | 职责 |
| --- | --- |
| 内容目录与公开判断 | 稳定课程／主题 ID、归属、可见性、项目主题校验 |
| 统一构建聚合 | 专题成员、主题篇数、分页数据、全站统计；汇总结果供各页面复用 |
| 专题页面与共享主题列表 | 聚合入口、主题详情、真实空状态和分页 |
| 布局与专题导航 | 当前页面上下文、左右栏顺序、响应式位置、Swup 更新 |
| SiteStats | 展示统一指标与日期，复用 WidgetLayout 的外观 |
| Search／SEO／兼容路径 | 继续索引唯一公开正文，生成正确链接，保留旧地址与锚点 |

不引入 CMS、数据库、搜索后端或新的 UI 框架。静态构建完成内容归类、统计和分页，客户端不下载整站文章数据计算这些指标。

500+ 篇时，侧栏只携带当前专题的主题及数量；课程讲次仅携带当前课程的上下文，不展开全站文章。每页最多 25 个列表项，不生成所有类型、主题、标签组合。聚合应复用单次构建结果；开发时内容变化必须使结果更新，不能留下跨构建的陈旧缓存。

## 9. 兼容与内容保全

- 取消 Notes 导航项，不删除 `/notes/[slug]/`、旧 `/blog/...`、作者兼容页、原图地址或旧标题锚点。
- 保留 `/notes/` 和现有分页供旧书签访问，不通过批量重命名 slug 改造页面层级。
- 保留 `/topics/` 的跨专题意义；专题内主题链接进入当前专题的主题页，跨专题关联继续进入全站主题页。
- 为新增公开集合页生成正确 canonical；分页使用自己的规范地址，不将所有页规范到第一页。noindex 的本地预览规则继续生效。
- 旧 Research 用途页继续有效；新增主题路径采用独立的 `topics` 前缀，避免与 logs／ideas／experiments 冲突。
- 不批量修改正文、原图、文章主题或日期；必要的模型扩展与展示适配不改变既有业务 ID。

## 10. 验收标准

1. 桌面和手机主导航均没有 Notes，四个入口正确；原文章和兼容链接继续可达。
2. 当前公开文章仍为 44，组成仍为 31／12／1／0；受控主题为 9，标签为 21，数字由内容得出。
3. Courses 按讲次阅读；Papers／Research 按主题浏览；Projects 保留真实空状态。主题成员跨主题重复展示不增加全站文章数。
4. draft、unlisted、集合介绍、空正文不进入公开主题列表、计数、统计或搜索；未知主题 ID 报错到对应内容。
5. 从 Courses 切换 Papers、Research、文章，再返回时，左侧导航、选中状态、课程讲次和右侧目录均正确；音乐保持单实例及用户开始的播放状态。
6. 统计的字数与共享正文规则一致，英文不按字母计数；运行时长按上海自然日、起点 2025-01-01 验证。最后活动覆盖未知日期、更新老文章、未来日期及无 JavaScript 情况。
